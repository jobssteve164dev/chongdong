# 地理位置防护使用说明

## 概述

虫洞提供地理位置相关的防护配置、风险检查和部分出口观测。配置已启用只表示策略存在；只有取得真实运行时或外部观测证据的项目才能标记为通过，其余项目会明确显示“未验证”。

## 防护机制

### 1. DNS防护
- **严格模式**: 仅接受 DoH/DoT 上游；没有安全上游时失败关闭
- **代理内解析**: 本地 SOCKS 入口可用时，严格模式通过该入口发起 DoH/DoT
- **验证边界**: 当前不能证明操作系统和其他进程的全部 DNS 查询都经过虫洞

### 2. IPv6防护
- **接口观测**: 检查本机是否存在全局 IPv6 地址
- **策略配置**: 可关闭代理核心的 IPv6 路径；这不等价于修改整个操作系统的 IPv6 状态

### 3. WebRTC防护
- **Chromium策略**: 限制非代理 UDP，并在严格模式下对 ICE 相关调用做保护
- **验证边界**: 未取得真实 ICE 候选地址前只显示“策略已启用”，不显示“无泄露”

### 4. 浏览器指纹防护
- 当前仅有 TLS 指纹相关配置；尚未实现并验证时区、语言、屏幕、Canvas 的完整隔离。
- TLS 指纹保护必须由外部握手观测验证，读取配置开关不能作为通过证据。

### 5. 网络接口防护
- 网络接口与 MAC 检查目前属于风险提示能力，不承诺修改或隐藏整个操作系统的接口信息。

### 6. HTTP/2.0特定防护
- 连接隔离、头部表、时序和协议降级目前包含配置与统计入口；没有外部流量观测时不会标记为验证通过。

### 7. 代理链验证
- 当前可以观测核心进程、入口端口和部分出口 IP；逐跳身份与逐跳出口仍需后续受控观测设施。
- 动态链只在找到可用节点时启动，不再用空链或静态配置冒充动态链成功。

## 使用方法

### 1. 启用防护功能

在应用设置中启用以下选项：

```typescript
// 在设置中启用所有防护功能
const settings = {
  // DNS防护
  enableDnsLeakProtection: true,
  dnsLeakProtectionMode: 'strict',
  
  // IPv6防护
  enableIpv6LeakProtection: true,
  ipv6LeakProtectionMode: 'strict',
  
  // WebRTC防护
  enableWebRTCLeakProtection: true,
  webRTCLeakProtectionMode: 'strict',
  
  // HTTP头部防护
  enableHttpHeaderProtection: true,
  httpHeaderProtectionMode: 'strict',
  
  // 时序泄露防护
  enableTimingLeakProtection: true,
  timingLeakProtectionMode: 'strict',
  
  // MAC地址防护
  enableMacAddressProtection: true,
  macAddressProtectionMode: 'strict',
  
  // HTTP/2.0防护
  enableHttp2Protection: true,
  http2ProtectionMode: 'strict',
  http2ConnectionIsolation: true,
  http2HeaderTableCleanup: true,
  http2TimingObfuscation: true,
  http2ForceHttp1: false, // 根据需要设置
  http2SensitiveDomains: [
    'google.com',
    'facebook.com',
    'twitter.com',
    'instagram.com',
    'youtube.com',
    'amazon.com',
    'microsoft.com',
    'apple.com'
  ]
};
```

### 2. 运行地理位置泄露测试

```typescript
import { leakProtectionManager } from './services/leakProtectionManager';

// 执行完整的地理位置泄露测试
async function runGeolocationTest() {
  try {
    const result = await leakProtectionManager.runGeolocationLeakTest();
    
    console.log(`测试总分: ${result.overallScore}/100`);
    console.log('测试结果:', result.tests);
    console.log('改进建议:', result.recommendations);
    
  } catch (error) {
    console.error('测试失败:', error);
  }
}

// 应用全面的地理位置防护
async function applyProtection() {
  try {
    const success = await leakProtectionManager.applyComprehensiveGeolocationProtection();
    console.log(`防护应用结果: ${success ? '成功' : '失败'}`);
  } catch (error) {
    console.error('防护应用失败:', error);
  }
}
```

## 测试项目

地理位置泄露测试包括以下项目：

1. **IP地址泄露测试**: 检测真实IP地址是否泄露
2. **DNS泄露测试**: 检测DNS查询是否泄露真实位置
3. **WebRTC泄露测试**: 检测WebRTC是否泄露真实IP
4. **IPv6泄露测试**: 检测IPv6地址是否泄露
5. **浏览器指纹测试**: 检测浏览器指纹是否暴露位置信息
6. **时区泄露测试**: 检测时区信息是否泄露
7. **语言泄露测试**: 检测语言设置是否泄露位置
8. **代理链测试**: 检测代理链是否正常工作

## 结果语义

- **通过**：检查路径产生了真实观测证据，且未发现泄露。
- **失败**：观测到泄露或明确的不安全配置。
- **未验证**：只有配置状态，或缺少外部观测条件；未验证不会计为通过。
- 综合分数只统计有证据的通过项，不能替代逐项结果。

## 常见问题

### Q: 为什么应用仍然能知道我的地理位置？

A: 可能的原因包括：
1. 防护功能没有正确启用
2. 代理配置有问题，流量没有通过代理
3. 某些防护措施只是检测功能，没有实际防护
4. 存在其他未覆盖的泄露途径

### Q: 如何验证防护效果？

A: 建议：
1. 定期运行地理位置泄露测试
2. 使用在线IP检测服务验证
3. 检查代理链是否正常工作
4. 监控防护状态和日志

### Q: 防护功能会影响网络性能吗？

A: 可能会有轻微影响：
1. 连接隔离会增加连接数
2. 时序混淆会增加延迟
3. 头部清理会增加处理时间
4. 建议在性能和隐私之间找到平衡

## 最佳实践

1. **定期测试**: 建议每周运行一次地理位置泄露测试
2. **监控状态**: 定期检查防护状态和代理健康状态
3. **更新配置**: 根据测试结果调整防护配置
4. **备份设置**: 保存有效的防护配置
5. **日志监控**: 关注防护日志，及时发现异常
