# 规划蓝图：CF Edge/Workers Pages 中间加密代理与代理链集成
*   **状态**: [规划中]

## 1. 核心目标与验收标准 (Core Objective & Acceptance Criteria)

### a. 核心目标 (Core Objective)
*   在 Cloudflare Edge（Workers/Pages Functions）侧实现一层“中间加密”与请求混淆的可控中转层，实现：
    - **对 ISP 隐藏访问目标**：本地出站只与 CF 边缘域通信；目标域信息仅在边缘侧解封装。
    - **对访问目标隐藏客户端 IP**：目标站点仅看到 Cloudflare 边缘节点的出口 IP。
    - 与现有“代理链中间件架构”（`ProxyChainMiddlewareManager` + `TrafficRouter` + `ProtocolAdapter`）无缝集成为链中一环。

### b. 验收标准 (Acceptance Criteria)
*   `[ ]` 在 CF 上部署一份最小可行 Workers/Pages Functions（支持 Route 绑定或 Pages _worker.js）可将封装后的请求转发到任意目标域。
*   `[ ]` 本地客户端通过中间件链路，能以“CF 边缘域名”为唯一可见目的地完成外部站点访问（HTTPS 成功、HTTP 成功）。
*   `[ ]` 本地链路中加入防指纹中间件：时间整形、HTTP 头标准化（沿用 `TrafficRouter` 机制），且不破坏 TLS 透传。
*   `[ ]` 端到端的错误诊断路径清晰，包含可观测事件（连接开始/结束、错误、流量统计）。
*   `[ ]` 通过“被动检测指标”审计（UA、连接模式、Header 集合、缓存命中等）无明显代理指纹；不触发常见滥用策略。

## 2. 现状分析与复用性尽职调查 (Current State Analysis & Reuse Due Diligence)

### a. 代码考古（复用优先）
*   已有中间件核心：
    - `src/main/proxyChainMiddlewareManager.ts`：生命周期与协调
    - `src/main/trafficRouter.ts`：TCP 转发、时间泄露防护、HTTP 头标准化、行为分析
    - `src/main/protocolAdapter.ts`：节点进程管理（sing-box）、端口校验
    - `src/shared/types/middleware.ts`：`IAdapter` 接口与事件模型
*   结论：
    - 当前链路是“本地多进程 + TCP 路由器”的组合。新增 CF Edge 作为“远端中继”最好通过“基于 HTTPS 的应用层封装”接入，避免 Workers TCP 直连限制带来的约束。

### b. Cloudflare 能力与限制（官方文档要点）
*   Workers/Pages Functions 运行时：
    - 支持 `fetch()` 任意外部 HTTPS 出站；支持 `ReadableStream/TransformStream` 流式处理；支持 WebCrypto SubtleCrypto（AES-GCM 等）。
    - Sockets：无原生 TCP 直连用于任意端口（仅 HTTP(S)/WebSocket 出站）。
    - 资源限制：CPU 时间、子请求数（subrequests）、脚本大小、计费限额需遵循平台配额。
*   Pages Functions 与 Workers 差异：Pages Functions 通过 `_worker.js` 提供与 Workers 几乎一致的处理模型，部署、版本化更贴近静态站点与CI流程。

## 3. 技术方案与架构设计 (Technical Approach & Architecture Design)

### a. 总体架构
```
客户端 (系统代理 指向本地) 
  → TrafficRouter(本地TCP入口, 中间件时间/头部整形)
  → ProtocolAdapter 链(本地若干Sing-box实例，可选)
  → HTTPS 隧道封装(到 CF 边缘域: e.g. https://edge.example.com)
  → Cloudflare Workers/Pages (_worker.js)
     → 解封装：目标域、方法、路径、头部最小化重建
     → fetch() 到真实目标域（可选：再经下游代理）
     ← 边缘回传响应（可流式）
  ← 本地中间件回写给客户端
```

### b. 传输与封装协议
*   采用“应用层封装 + 流式加密”的方式：
    - 客户端侧（本地中间件）将原始请求以 JSON+二进制分片或纯二进制帧封装为 HTTPS POST/CONNECT 风格请求至 CF；
    - 边缘使用 WebCrypto SubtleCrypto 进行对称解密（AES-GCM），仅保留必要元信息（method、path、headers allowlist）。
*   密钥协商：
    - v1 最简：预共享密钥（PSK）+ 版本/nonce/exp 旋转；
    - v2 可选：ECDH 临时密钥交换（发送端曲线25519 公钥，边缘派生会话密钥）。
*   分片与流控：
    - 使用 `ReadableStream`/`TransformStream` 在 CF 侧实现端到端流式转发，降低内存峰值，减少超时风险。

### c. 与现有中间件的集成点
*   入口仍为 `TrafficRouter` 的 TCP 监听端口；在“HTTP 明文”首包可复用头标准化；TLS 流量保持透明转发。
*   新增一个“CF Edge 适配器”（轻量）：
    - 类型上实现 `IAdapter` 接口，但本质不拉起本地进程；而是作为上游“出口路由”策略，将所有外发目标统一封装到 CF 边缘域。
    - 若保持既有 `ProtocolAdapter` 链，CF Edge 可以作为“最终节点”的远端终出站。

### d. Pages Functions/Workers 侧实现要点
*   路由器：单入口 `_worker.js` 或 Multi-route handlers；
*   核心逻辑：
    - 鉴权与限速：校验 HMAC/时间戳/nonce；基于 IP/UA/路径 速率限制；
    - 解封装与最小化转发：白名单化请求头（Host、Accept、UA 等少量标准头，剔除 X-Forwarded-For/CF-Connecting-IP 等客户端指纹），目标域从加密载荷取得；
    - fetch 出站：遵循 keepalive、HTTP/2/3 自动协商；开启 streaming；
    - 返回时最小化响应头；按需缓存静态可缓存请求；
    - 观测：仅在 server-side console/sentry 上报摘要（避免向客户端泄露内部）。

### e. 反检测策略（最小可见性原则）
*   Header 标准化：
    - 入站：在本地 TrafficRouter 已做首包标准化；
    - 出站（CF → 目标）：使用一组与主流浏览器/常见 Bot 不冲突的标准 Accept/UA 组合；
*   行为整形：
    - 时间抖动：本地已实现；可在边缘对超短请求增加微抖动避免“完美节奏”指纹；
*   资源/配额合规：
    - 控制子请求数；对大文件传输采用分块/Range；
    - 对热门静态资源开启 Cache TTL 或 `cacheTtlByStatus`；

## 4. 任务分解与上下文锚点 (Task Breakdown & Context Anchors)

- `[ ]` 后端本地：新增“CF Edge 适配器”骨架（实现 `IAdapter`，不启动进程，暴露配置：边缘域、PSK、公钥）。
- `[ ]` 本地中间件：在 `TrafficRouter.setupDataForwarding` 添加“可选应用层封装输出器”（当链尾为 CF Edge 时启用）。
- `[ ]` CF 边缘：创建 Pages 项目与 `_worker.js`，实现解封装、鉴权、白名单化转发与流式回传。
- `[ ]` 安全：实现 PSK 鉴权与时间窗校验、nonce 去重；配置 KV/DO/R2 以支持密钥轮换与速率计数。
- `[ ]` 观测：在中间件与 Workers 侧统一事件模型（连接开始/结束、错误、流量统计），与现有监控面板对齐。
- `[ ]` 验证：端到端访问常见站点（HTTP/HTTPS）、测速、下载大对象、断点续传（Range）。

## 5. 风险评估与规避 (Risk Assessment & Mitigation)

- **平台限制**：Workers 无原生 TCP，方案基于 HTTPS 应用层封装与 fetch 出站；规避：不在边缘做 TCP 级代理。
- **配额/费控**：子请求/CPU/带宽费用；规避：缓存静态、限制长连接会话数、流控与黑名单。
- **检测风险**：异常头部与节奏；规避：严格最小化与标准化头、时间抖动、避免透传指纹字段。
- **法务与TOS**：必须遵守 Cloudflare ToS，避免大规模反代滥用场景；必要时走自有域+私有路由。

## 8. (可选) 伪代码与接口草案

### a. 本地封装器（概念示例）
```ts
// wrapOutgoing.ts
export async function wrapAsEdgeEnvelope(buf: Buffer, key: CryptoKey, meta: { host: string; port?: number; method?: string; path?: string; headers?: Record<string,string> }) {
  const nonce = crypto.getRandomValues(new Uint8Array(12));
  const payload = CBOR.encode({ meta, chunk: buf });
  const cipher = await crypto.subtle.encrypt({ name: 'AES-GCM', iv: nonce }, key, payload);
  return { nonce: Buffer.from(nonce), cipher: Buffer.from(cipher) };
}
```
