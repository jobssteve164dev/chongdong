# 规划蓝图：HTTP/2.0 隐私加固与地理位置防护
*   **状态**: [进行中]

## 1. 核心目标与验收标准 (Core Objective & Acceptance Criteria)

### a. 核心目标 (Core Objective)
*   在保持 HTTP/2.0 性能优势前提下，收敛所有出网与解析路径、标准化指纹与头部，避免因 HTTP/2.0（含 H3/QUIC 升级、连接合并、TLS/H2 指纹）导致的地理位置与真实网络特征暴露，实现与 HTTP/1.1 一致的隐私保护等级。

### b. 验收标准 (Acceptance Criteria)
*   [ ] 在 HTTP/2 模式下访问 `ipinfo.io/json` 与 `ipapi.co/json`，返回 IP 与国家/地区与 HTTP/1.1 下保持一致（均为代理出口）。
*   [ ] QUIC/HTTP/3 升级被禁用或完全经代理通道转发（无本机 UDP/443 直连）。
*   [ ] 敏感域（登录/支付/大厂 SSO）默认强制 HTTP/1.1 或启用 HTTP/2 连接隔离（不跨域合并）。
*   [ ] `Accept-Language`、`X-Forwarded-*`、`Via` 等头部被标准化/清理，不暴露本地域偏好与中间设备信息。
*   [ ] DNS 解析统一走代理/DoH，严禁本地直连解析；IPv6 泄露被阻断。
*   [ ] 新增/强化的检测脚本与应用自测（Leak Tester）在 HTTP/1.1 与 HTTP/2 均通过（总体评分≥95/100）。

## 2. 现状分析与复用性尽职调查 (Current State Analysis & Reuse Due Diligence)

### a. 复用性尽职调查
*   **搜索关键词**: `http2`, `QUIC`, `Alt-Svc`, `dns`, `DoH`, `Accept-Language`, `X-Forwarded`, `utls`, `TLS fingerprint`。
*   **搜索范围**: `src/main/services/`, `src/main/index.ts`, `src/main/proxyManager.ts`, `src/main/proxyChainConfigGenerator.ts`, `src/shared/types/`。
*   **发现与结论**:
    *   已有 `HttpProtocolManager`（连接隔离、敏感域清单、协议选择）；需与系统出入口联动并在策略上启用。
    *   已有 `TlsFingerprintProtectionService`（模板化 TLS 指纹）；`proxyChainConfigGenerator` 对启用 TLS 的出站已注入 uTLS（基于设置）。
    *   已有 `HttpHeaderProtectionService`（标准化头部、去敏）；尚未集成到请求路径，需在网络层/引擎配置中落地。
    *   已有 `GeolocationProtectionService` 与 `GeolocationLeakTester`（框架完备，检测/执行多为占位，需要实装）。
    *   `src/main/index.ts` 已配置 WebRTC 防护，但尚未禁用 QUIC；DNS 有 DoH/DoT 能力（在 `proxyManager`/`renderer/utils/proxyEngine` 的配置生成中），需要统一收敛至代理出口。
    *   结论：以“复用现有能力、补齐落地缺口”为主，无需重写。

### b. 潜在影响分析
*   禁用 QUIC/Alt-Svc 可能影响少量站点的首包性能；可通过代理内置的 TCP/TLS 优化与缓存缓解。
*   头部去敏可能影响极个别依赖特定 `Accept-Language` 的站点本地化展示；提供可切换模板与白名单。
*   严格 DNS 收敛与 IPv6 抑制可能影响局域网直连的名称解析；提供可配置例外（.local、内网域）。

## 3. 技术方案与架构设计 (Technical Approach & Architecture Design)

### a. 路由/通道层
*   Electron 主进程禁用 QUIC：`app.commandLine.appendSwitch('disable-quic')`，阻断 HTTP/3 升级路径。
*   统一 DNS 出口：在代理引擎配置层启用经代理的 DoH/DoT；`GeolocationProtectionService` 的 `forceProxyDns` 与 `dnsOverHttps` 实装；在 DNS 管理器内禁直连。
*   HTTP/2 策略：`HttpProtocolManager` 对敏感域强制 HTTP/1.1 或启用连接隔离；按域限并发，关闭跨域连接合并。

### b. 指纹/头部层
*   TLS 指纹：默认 `chrome` 模板；通过设置项统一注入 uTLS（现有逻辑已支持）。
*   HTTP 头部：标准化 `Accept-Language`（中性 en-US）、移除 `X-Forwarded-*`/`Via` 等敏感头；为特定站点提供白名单可覆盖。

### c. 名称解析与地址栈
*   全量解析经代理 DoH；禁本地直连；IPv6 在严格模式下禁用或隧道化。

### d. 验证与监控
*   新增 curl/脚本：对比 `--http2` 与 `--http1.1` 的出口一致性；监控 UDP/443 端口活动为 0；Leak Tester 分场景评分。

## 5. 风险评估与应对策略 (Risk Assessment & Mitigation Plan)

*   风险1：禁 QUIC 导致个别站点性能下降。
    *   应对：保持 HTTP/2；在代理链端优化 TCP；提供开关与例外。
*   风险2：头部去敏影响本地化体验。
    *   应对：白名单域名保留原头部；支持模板切换。
*   风险3：严格 DNS 收敛影响内网解析。
    *   应对：规则中允许 `.local`、内网域直连/特例。

## 6. 集成验证路径 (Integration Validation Path)

1. 运行应用，确保主进程日志提示已禁用 QUIC。
2. 使用 `curl --http1.1 https://ipinfo.io/json` 与 `curl --http2 https://ipinfo.io/json`，两者 IP 与国家/地区一致。
3. 访问典型敏感域（如登录页），确认连接被隔离且未跨域合并；头部与 TLS 指纹模板正常。
4. 运行 Leak Tester，HTTP/1.1 与 HTTP/2 下综合评分≥95/100。
