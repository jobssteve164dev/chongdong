**添加代理端口验证机制**
```typescript
// src/main/proxyManager.ts
// 验证端口是否可用
let resolved = false;
const port = finalConfig.inbounds?.[0]?.listen_port || 1080;

// 等待更长时间让进程完全启动，然后验证端口
setTimeout(async () => {
  if (!resolved) {
    try {
      // 验证SOCKS端口是否可用
      const isPortReady = await this.checkPortReady('127.0.0.1', port, 5000);
      if (isPortReady) {
        console.log(`Sing-box 端口 ${port} 验证成功`);
        resolved = true;
        resolve();
      } else {
        console.error(`Sing-box 端口 ${port} 验证失败`);
        childProcess.kill();
        resolved = true;
        reject(new Error(`Sing-box 启动失败: 端口 ${port} 不可用`));
      }
    } catch (error) {
      console.error(`Sing-box 端口验证异常:`, error);
      childProcess.kill();
      resolved = true;
      reject(new Error(`Sing-box 启动失败: 端口验证异常`));
    }
  }
}, 2000); // 等待2秒让进程完全启动
```

## 5. 自我评估与学习 (Self-Assessment & Learning)

*   **遇到的挑战**: 
    - 需要从复杂的日志信息中识别多个相互关联的问题
    - GPU信息序列化问题需要深入理解Electron的异步API
    - 代理端口验证需要平衡启动速度和可靠性
*   **学到的教训**: 
    - 崩溃监控器本身的错误处理必须更加健壮，避免连锁崩溃
    - 代理启动验证不能仅依赖进程启动成功，必须验证端口可用性
    - 系统代理设置必须在代理启动成功后立即执行，确保状态同步
    - 异步操作（如GPU信息获取）必须正确处理Promise和序列化问题
