# 系统状态卡片与连接历史管理优化报告

## 1. 任务概述 (Task Overview)

- **任务ID/名称**: 系统状态卡片与连接历史管理优化 - 实现真实系统监控与代理模式切换历史隔离
- **来源**: 用户反馈"首页系统状态卡片数据没有变化"和"代理链切换至节点模式时历史连接显示错误"
- **完成时间**: 2025-09-03 21:00:00
- **影响范围**: 仪表盘系统状态监控、代理模式切换、连接历史管理

## 2. 问题分析 (Problem Analysis)

### a. 系统状态卡片问题
- **现象**: 首页系统状态卡片显示静态硬编码数据（CPU 30%、内存 45%、系统代理 75%）
- **原因**: 系统状态卡片使用硬编码百分比，未连接真实的系统监控数据
- **影响**: 用户无法看到真实的系统资源使用情况

### b. 连接历史管理问题
- **现象**: 从代理链模式切换至节点模式时，监控统计页面仍显示代理链的连接历史
- **原因**: 
  1. `proxyManager.getStats()` 优先返回中间件统计，即使中间件已停止
  2. 启动节点模式前未正确停止代理链中间件
  3. 停止代理时未清理中间件状态
- **影响**: 连接历史数据混乱，用户无法区分不同代理模式下的连接记录

## 3. 解决方案 (Solution)

### a. 系统状态卡片真实数据实现

#### 技术方案
- 启用已存在的 `rendererSystemMonitor` 系统监控组件
- 通过 IPC 连接主进程 `systemMonitor` 获取真实系统指标
- 实现实时数据更新和状态监听

#### 主要变更
1. **启用系统监控** (`src/renderer/pages/Dashboard.tsx`)
   ```typescript
   // 取消注释并启用系统监控
   import { rendererSystemMonitor, SystemMetrics } from '../utils/systemMonitor';
   
   const [systemMetrics, setSystemMetrics] = useState<SystemMetrics>({
     cpuUsage: 0,
     memoryUsage: 0,
     systemProxyEnabled: false,
     timestamp: Date.now()
   });
   
   // 系统监控相关
   useEffect(() => {
     const initSystemMonitoring = async () => {
       try {
         // 获取初始系统指标
         const initialMetrics = await rendererSystemMonitor.getSystemMetrics();
         setSystemMetrics(initialMetrics);
         
         // 添加系统指标更新监听器
         const metricsListener = (metrics: SystemMetrics) => {
           setSystemMetrics(metrics);
         };
         
         rendererSystemMonitor.addListener(metricsListener);
         
         // 启动系统监控
         await rendererSystemMonitor.startMonitoring();
         
         return () => {
           rendererSystemMonitor.removeListener(metricsListener);
         };
       } catch (error) {
         console.error('初始化系统监控失败:', error);
       }
     };
     
     initSystemMonitoring();
   }, []);
   ```

### b. 连接历史管理优化

#### 技术方案
- 修复 `proxyManager.getStats()` 逻辑，确保只在中间件运行时返回中间件统计
- 在启动节点模式前强制停止代理链中间件
- 在停止代理时清理所有中间件状态

#### 主要变更

1. **修复统计获取逻辑** (`src/main/proxyManager.ts`)
   ```typescript
   public async getStats(): Promise<any> {
     try {
       // 优先：仅当中间件代理链"正在运行"时才汇总其统计
       const mm = this.middlewareManager;
       if (mm && mm.getStatus().status === 'running') {
         try {
           const chainStats: any = mm.getTrafficStats();
           const history = (mm as any).getConnectionHistory?.() || [];
           // 异步刷新一次连接元数据（远端域名/端口）
           try { await (mm as any).refreshConnectionMetadata?.(); } catch {}
           // middleware 返回的是 bytes 级别统计，这里统一映射为渲染端使用的字段
           return {
             totalUpload: chainStats.bytesReceived || 0,
             totalDownload: chainStats.bytesSent || 0,
             uploadSpeed: 0,
             downloadSpeed: 0,
             activeConnections: chainStats.connections || 0,
             connections: history,
             totalConnections: 1
           };
         } catch (e) {
           console.warn('[ProxyManager] 获取中间件统计失败，回退到进程统计:', e);
         }
       }
       
       // 获取所有运行中的进程统计（节点模式）
       // ... 原有的节点模式统计逻辑
     }
   }
   ```

2. **IPC 处理器优化** (`src/main/index.ts`)
   ```typescript
   // 启动节点模式前停止中间件
   ipcMain.handle('proxy:startSingbox', async (_, config) => {
     try {
       console.log(`开始启动 Sing-box...`);
       // 切换到节点模式前，确保中间件已停止
       try { await proxyManager.stopMiddleware(); } catch (e) { console.warn('[IPC] stopMiddleware ignore:', e); }
       await proxyManager.startSingbox(config);
       return { success: true };
     } catch (error) {
       return { success: false, error: error instanceof Error ? error.message : 'Unknown error' };
     }
   });
   
   // 停止时清理所有状态
   ipcMain.handle('proxy:stop', async () => {
     try {
       // 优先停止中间件，再停止所有单引擎进程
       try { await proxyManager.stopMiddleware(); } catch (e) { console.warn('[IPC] stopMiddleware ignore:', e); }
       await proxyManager.stopAll();
       return { success: true };
     } catch (error) {
       return { success: false, error: error instanceof Error ? error.message : 'Unknown error' };
     }
   });
   ```

## 4. 技术实现细节 (Technical Implementation)

### a. 系统监控架构
- **主进程**: `SystemMonitor` 类负责获取真实系统指标（CPU、内存、系统代理状态）
- **渲染进程**: `RendererSystemMonitor` 类负责接收和分发系统指标更新
- **IPC 通信**: 通过 `system:get-metrics` 和 `system:metrics-updated` 事件实现数据同步
- **更新频率**: 每2秒更新一次系统指标

### b. 代理模式切换机制
- **中间件模式**: 使用 `ProxyChainMiddlewareManager` 管理代理链连接和统计
- **节点模式**: 使用传统的 sing-box/xray/clash 进程管理
- **模式切换**: 启动新模式前强制停止旧模式，确保状态隔离
- **统计隔离**: 根据当前运行模式返回对应的统计数据和连接历史

### c. 连接历史数据结构
```typescript
interface ConnectionHistory {
```
