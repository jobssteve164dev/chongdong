**Dashboard 端口占用弹窗监听器**
```typescript
useEffect(() => {
  const handlePortInUse = (data: { port: number; processId: string }) => {
    Modal.confirm({
      title: '端口被占用',
      content: (
        <div>
          <p>端口 {data.port} 已被其他进程占用，无法启动代理服务。</p>
          <p>可能的原因：</p>
          <ul>
            <li>之前的代理进程未完全退出</li>
            <li>其他应用正在使用该端口</li>
            <li>系统代理已启用</li>
          </ul>
          <p>是否要终止占用该端口的进程？</p>
        </div>
      ),
      okText: '终止进程',
      cancelText: '取消',
      onOk: async () => {
        const result = await window.electron.ipcRenderer.invoke('proxy:killProcessOnPort', data.port);
        if (result.success) {
          message.success(result.message);
        } else {
          message.error(result.message || '操作失败');
        }
      }
    });
  };

  window.electron.ipcRenderer.on('proxy:portInUse', handlePortInUse);
}, []);
```

## 5. 自我评估与学习 (Self-Assessment & Learning)

*   **遇到的挑战**: 
    - 初始错误日志显示的是打包后的代码，需要从源文件分析问题
    - 端口占用检测的异步逻辑导致通知发送时机不当
    - 类型定义缺失导致的构建失败需要额外处理
*   **学到的教训**: 
    - 模块循环依赖是导致"暂时性死区"错误的常见原因，应该避免复杂的单例模式实现
    - 在错误处理中，通知发送应该在应用崩溃之前完成，避免使用可能失败的异步检查
    - 在添加新功能时，需要确保所有相关页面都有相应的事件监听器
    - 构建失败时应该优先检查依赖包和类型定义是否完整
