## 🔍 问题深度分析

### 1. 协议交换日志分析

**macOS发送的SCCRQ**：
```
c802001400000000000000008008000000000006
```

**我们的SCCRP响应**：
```
c802001400010000000100018008000000000002
```

### 2. 关键问题识别

#### A. 隧道ID处理问题
- **问题**：macOS发送隧道ID=0，但我们每次都分配新ID
- **影响**：macOS无法识别我们的响应属于哪个隧道
- **标准**：应该使用macOS发送的隧道ID或协商新ID

#### B. 序列号处理问题
- **问题**：macOS发送Ns=0, Nr=0，我们响应Ns=1, Nr=1
- **影响**：序列号不匹配可能导致协议状态混乱
- **标准**：应该正确递增序列号并确认对方的序列号

#### C. AVP格式问题
- **问题**：我们的AVP格式可能与L2TP标准不符
- **影响**：macOS无法正确解析我们的属性值对
- **标准**：需要严格按照RFC 2661 L2TP标准实现

### 3. 技术细节分析

## 🛠️ 解决方案建议

### 1. 立即修复（高优先级）

#### A. 隧道ID协商
```typescript
// 修改handleSccrq方法
private handleSccrq(rinfo: any, tunnelId: number, ns: number, nr: number): void {
  // 如果macOS发送隧道ID=0，分配新ID
  const assignedTunnelId = tunnelId === 0 ? this.nextTunnelId++ : tunnelId;
  
  // 保存隧道信息
  this.activeTunnels.set(assignedTunnelId, {
    remoteAddress: rinfo.address,
    remotePort: rinfo.port,
    ns: 0,
    nr: 0
  });
  
  this.sendSccrp(rinfo, assignedTunnelId, 0, 1); // 确认对方的序列号
}
```

#### B. 正确的序列号处理
```typescript
// 修改sendSccrp方法
private sendSccrp(rinfo: any, tunnelId: number, ns: number, nr: number): void {
  // 使用正确的序列号
  const response = Buffer.alloc(20);
  
  // L2TP头部
  response.writeUInt16BE(0xC802, 0);
  response.writeUInt16BE(20, 2);
  response.writeUInt16BE(tunnelId, 4);
  response.writeUInt16BE(0, 6);
  
  // 控制消息头部 - 正确的序列号
  response.writeUInt16BE(0, 8);      // Ns = 0 (我们的初始序列号)
  response.writeUInt16BE(1, 10);     // Nr = 1 (确认对方的序列号)
  
  // 标准Message Type AVP
  response.writeUInt16BE(0x8000, 12); // M=1, 标准AVP
  response.writeUInt16BE(6, 14);      // AVP长度 = 6
  response.writeUInt16BE(0, 16);      // Vendor ID = 0
  response.writeUInt16BE(1, 18);      // Attribute Type = 1 (Message Type)
  
  // 需要添加Message Type值，所以需要22字节
  const finalResponse = Buffer.alloc(22);
  response.copy(finalResponse, 0, 0, 20);
  finalResponse.writeUInt16BE(2, 20); // Message Type = 2 (SCCRP)
  
  // 修正长度
  finalResponse.writeUInt16BE(22, 2);
  finalResponse.writeUInt16BE(8, 14); // AVP长度 = 8
  
  this.sendL2tpMessage(rinfo, finalResponse);
}
```
