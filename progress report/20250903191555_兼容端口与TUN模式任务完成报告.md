## 任务完成报告：兼容端口即时生效与 TUN 模式完善

### 背景与目标
- 放弃 L2TP 方案后，已切换到基于 TUN 的全局代理实现，并引入兼容端口（Compatibility Proxy）以适配显式代理端口的应用（如 Cursor）。
- 本次目标：
  - 使“启用兼容端口”设置即时生效（无需重新连接 VPN）。
  - 提供取消 Cursor 显式代理端口的操作指引，确保走 TUN 流量。
  - 巩固 TUN 模式的稳定性与可观测性。

### 已完成事项
- 主进程监听设置变化，VPN 模式下即时启停兼容端口转发器：
  - `settings:updated` 触发时，若当前为 VPN 模式，立即根据 `enableCompatProxy`、端口变更来启停 `CompatPortForwarder`。
- 兼容端口转发器（Compatibility Proxy）
  - 在本地监听如 `1080`（可配置），把连接转发到实际代理入口端口（由代理链中间件或全局入口确定）。
  - 在 `applyVpnMode` 与 `settings:updated` 处集成，保证随设置实时生效。
- TUN 模式稳定性与状态正确性：
  - 启动 TUN 前停止中间件，避免端口/流程冲突。
  - `osascript` 提权运行 `tun2socks`，PID/日志文件管理完善。
  - `TunController.isRunning` 识别 `EPERM` 场景为“进程存在（已提权）”。
- `sing-box` 配置与进程管理：
  - 当 `enableTun=true` 强校验配置内必须存在 `tun` inbound；缺失则拒绝启动并上报错误。
  - VPN 模式抑制系统代理设置，避免与 TUN 冲突。
- 代理链配置生成：
  - `generateChainConfig` 在无节点时也生成基础可运行配置（mixed inbound + direct out + tun-in 路由）。
  - 为 `tun-in` 流量添加路由规则以穿越代理链。
- 核心下载器：
  - 完善 `tun2socks` ZIP 包下载与解压安装流程（临时目录解压、可执行文件定位并移动）。
- UI 与文案：
  - 设置页新增“兼容性代理”相关开关与端口配置项；VPN 模式说明更新为 TUN。

### 用户操作指引：取消 Cursor 显式代理端口
- 在 Cursor 设置（Cmd+,）中搜索“proxy”，清空并保存：
  - `HTTP: Proxy` → 置空
  - `HTTP: Proxy Authorization` → 置空
  - 可选：`HTTP: Proxy Support` → `off`
  - 重启 Cursor
- 或者打开 Settings(JSON) 删除/置空：
```json
"http.proxy": "",
"http.proxyAuthorization": "",
"http.proxySupport": "off"
```
- 清理环境变量（若曾从终端带入）：
```bash
launchctl unsetenv HTTP_PROXY
launchctl unsetenv HTTPS_PROXY
launchctl unsetenv ALL_PROXY
launchctl unsetenv NO_PROXY
launchctl unsetenv http_proxy
launchctl unsetenv https_proxy
launchctl unsetenv all_proxy
launchctl unsetenv no_proxy
```
- 之后从 Dock/Launcher 启动 Cursor，避免继承带代理环境变量的终端会话。

### 验证清单
- TUN 有效性：
  - `ifconfig` 应存在 `utun*` 接口；`scutil --dns` 检查 DNS；`netstat -rn` 路由指向符合预期。
  - 应用内“VPN 状态”为“已连接”；`tun:diagnose` 返回正常。
- 兼容端口即时生效：
  - 在设置中切换“启用兼容端口”与端口号，实时验证端口监听变化与转发可用性。
- Cursor 取消显式代理后：
  - `Developer Tools` Console 中 `process.env.HTTP_PROXY || process.env.http_proxy` 为空。
  - `fetch('http://connectivitycheck.gstatic.com/generate_204').then(r=>r.status)` 返回 `204`。
  - 若需显式代理测试，将其指向应用的兼容端口（如 `127.0.0.1:1080`）；否则保持不配置由 TUN 接管。

### 已知风险与建议
- 若本机存在其他占用兼容端口（如 `1080`）的软件，需要更换端口或先关闭冲突进程。
- 提权执行受系统策略影响（如权限弹窗被拒绝）；需确保首次授权允许。
- 个别应用可能内置直连或自带防代理策略，必要时结合规则或进程级路由策略进一步细化。
