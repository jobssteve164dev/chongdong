## 2. 核心实现 (Core Implementation)

### a. 方法论/设计思路
- 在主进程聚合真实统计路径，复用现有中间件（TrafficRouter + ProtocolAdapter）采集数据，避免重复造轮子。
- 将中间件的总流量统计与连接事件通过 `ProxyManager.getStats()` 返回给渲染端，保证仪表盘与监控页统一从主进程取数。
- 连接历史：TrafficRouter 维护 per-connection 计数，管理器聚合 CONNECTION_START/TRAFFIC_FLOW/CONNECTION_END 事件，形成列表；补充解析 HTTP 首包的 Host 信息，尽量显示远端域名与端口。

### b. 主要变更文件 (Key Changed Files)
- `MODIFIED`: `src/main/proxyManager.ts`（在中间件模式返回总字节与连接历史；异步刷新元数据）
- `MODIFIED`: `src/main/proxyChainMiddlewareManager.ts`（聚合监控事件、维护 `connectionHistory`、暴露 `getConnectionHistory()`、修复类型与空值）
- `MODIFIED`: `src/main/trafficRouter.ts`（按连接累计上传/下载、发出连接事件；解析HTTP Host用于显示远端域名；修复严格类型）
- `MODIFIED`: `src/main/protocolAdapter.ts`（可选开启轻量 `clash_api` 端口并提供 `getRecentConnections()`；不影响主逻辑）

## 4. 影响与风险评估 (Impact & Risk Assessment)

- **正面影响**:
  - 修复链模式下统计与连接历史缺失，提升可观测性。
  - 前后端数据口径统一（主进程聚合 → 渲染端展示）。
- **潜在风险/后续工作**:
  - HTTPS 站点的域名显示需要 TLS ClientHello 的 SNI 解析支持（可后续实现，影响范围仅在展示层）。
  - 解析首包逻辑保持轻量与健壮，必要时可加开关。

## 5. 自我评估与学习 (Self-Assessment & Learning)

- **遇到的挑战**:
  - 需要在不破坏现有链路的情况下补齐统计与连接事件；同时满足严格 TypeScript 配置。
- **学到的教训**:
  - 观测优于推断：通过在路由器层记录连接事件，比从多进程拉指标更稳。
  - 在严格可选属性设置下，赋值前必须判空、分支保护，避免 TS exactOptionalPropertyTypes 报错。
