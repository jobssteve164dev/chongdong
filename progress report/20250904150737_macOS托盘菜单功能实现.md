## 2. 核心实现 (Core Implementation)

### a. 方法论/设计思路
采用了Electron主进程与渲染进程分离的架构设计。托盘菜单在主进程中创建和管理，通过IPC机制与渲染进程通信获取最新数据。实现了数据同步机制，确保托盘菜单能够实时反映应用状态，包括代理模式、可用节点和已保存的代理链配置。

const saveChainConfigs = (configs: ChainConfig[]) => {
  Storage.set('chain_configs', configs); // 保持前端兼容性
  setChainConfigs(configs);
  
  // 同步到主进程：保存到磁盘并刷新托盘菜单
  try {
    (window as any).electron?.ipcRenderer?.invoke('chains:save', configs).catch(() => {
      // 失败则仅更新缓存
      (window as any).electron?.ipcRenderer?.invoke('chains:updateSaved', configs).catch(() => {});
    });
  } catch (_) {
    try { (window as any).electron?.ipcRenderer?.invoke('chains:updateSaved', configs); } catch {}
  }
};

## 5. 自我评估与学习 (Self-Assessment & Learning)

*   **遇到的挑战**: 
    *   macOS托盘图标可见性问题：最初使用template图标导致图标不可见，通过创建专用PNG图标并避免template模式解决
    *   重复托盘图标问题：通过添加创建检查逻辑防止重复创建
    *   数据同步问题：渲染进程保存的代理链配置无法在主进程托盘菜单中显示，通过实现IPC同步机制解决
    *   用户手动代码回退导致的代码状态不一致问题

*   **学到的教训**: 
    *   macOS托盘图标需要特别注意template模式的使用，非template图标在浅色/深色模式下都能正常显示
    *   Electron主进程与渲染进程的数据隔离需要主动设计同步机制，不能依赖共享状态
    *   在实现复杂功能时，需要建立清晰的错误处理和回退机制
    *   代码修改后需要及时验证，避免因用户手动操作导致的代码状态混乱
    *   托盘菜单的动态更新需要建立完善的数据流机制，确保UI与数据状态的一致性
