## 2. 核心实现 (Core Implementation)

### a. 方法论/设计思路
通过分析代码逻辑，发现问题的根源在于端口占用检测逻辑不完整。当代理引擎（sing-box、xray、clash）检测到端口被占用时，虽然发送了端口占用通知，但没有抛出异常，导致IPC处理程序仍然返回成功状态。修复方案是在检测到端口占用时立即抛出异常，确保调用方能够正确识别启动失败。

### b. 主要变更文件 (Key Changed Files)
*   `MODIFIED`: `src/main/proxyManager.ts` - 修复所有引擎启动方法的端口占用检测逻辑

### c. 关键代码片段

**修复后的端口占用检测逻辑**
```typescript
// 监听标准错误
childProcess.stderr.on('data', (data) => {
  const errorMessage = data.toString();
  console.error(`Sing-box stderr: ${errorMessage}`);
  
  // 检测端口占用错误
  if (errorMessage.includes('bind: address already in use')) {
    console.log('检测到端口占用，发送端口占用通知');
    // 通过 IPC 发送端口占用通知到渲染进程
    const { BrowserWindow } = require('electron');
    const windows = BrowserWindow.getAllWindows();
    if (windows.length > 0) {
      const port = config.inbounds?.[0]?.listen_port || 7890;
      const notificationData = { port, processId };
      windows[0].webContents.send('proxy:portInUse', notificationData);
    }
    
    // 终止子进程
    childProcess.kill();
    
    // 抛出异常，让调用方知道启动失败
    throw new Error(`端口 ${port} 已被占用，无法启动代理服务`);
  }
});
```
