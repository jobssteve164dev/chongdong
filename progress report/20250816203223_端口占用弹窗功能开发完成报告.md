## 2. 核心实现 (Core Implementation)

### a. 方法论/设计思路
采用了事件驱动的架构设计，通过 Electron 的 IPC 机制实现主进程与渲染进程之间的通信。当 Sing-box 进程检测到端口占用错误时，主进程通过 IPC 向渲染进程发送通知，渲染进程接收到通知后显示用户友好的确认弹窗，让用户决定是否终止占用端口的进程。

**主进程端口占用检测和通知发送**

```typescript
// src/main/proxyManager.ts
childProcess.stderr.on('data', (data) => {
  const errorMessage = data.toString();
  console.error(`Sing-box stderr: ${errorMessage}`);
  
  // 检测端口占用错误
  if (errorMessage.includes('bind: address already in use')) {
    console.log('检测到端口占用，发送端口占用通知');
    const { BrowserWindow } = require('electron');
    const windows = BrowserWindow.getAllWindows();
    if (windows.length > 0) {
      const port = config.inbounds?.[0]?.listen_port || 7890;
      const notificationData = {
        port: port,
        processId: processId
      };
      windows[0].webContents.send('proxy:portInUse', notificationData);
    }
  }
});
```

**渲染进程弹窗处理**
```typescript
// src/renderer/pages/ProxyManagement.tsx
const handlePortInUse = (event: any, data: { port: number; processId: string }) => {
  Modal.confirm({
    title: '端口被占用',
    content: (
      <div>
        <p>端口 {data.port} 已被其他进程占用，无法启动代理服务。</p>
        <p>可能的原因：</p>
        <ul>
          <li>之前的代理进程未完全退出</li>
          <li>其他应用正在使用该端口</li>
          <li>系统代理已启用</li>
        </ul>
        <p>是否要终止占用该端口的进程？</p>
      </div>
    ),
    okText: '终止进程',
    cancelText: '取消',
    onOk: async () => {
      const result = await window.electron.ipcRenderer.invoke('proxy:killProcessOnPort', data.port);
      if (result.success) {
        message.success(result.message);
      } else {
        message.error(result.message || '操作失败');
      }
    }
  });
};
```

## 4. 影响与风险评估 (Impact & Risk Assessment)

*   **正面影响**: 显著改善了用户体验，当遇到端口冲突时不再需要手动查找和终止进程，提供了直观的交互界面。减少了用户的技术门槛，提高了应用的易用性。
*   **潜在风险/后续工作**: 当前实现仅支持 macOS 和 Linux 系统的进程终止（使用 `lsof` 和 `kill` 命令），在 Windows 系统上需要适配相应的命令。建议后续添加更详细的进程信息显示，帮助用户了解具体是哪个应用占用了端口。

## 5. 自我评估与学习 (Self-Assessment & Learning)

*   **遇到的挑战**: 在实现过程中遇到了 IPC 通信问题，发现 `proxy:portInUse` 通道没有在 preload 脚本中正确配置，导致渲染进程无法接收到通知。通过添加调试信息成功定位并解决了这个问题。
*   **学到的教训**: 在实现跨进程通信功能时，必须确保所有相关的 IPC 通道都在 preload 脚本中正确配置。调试信息的添加对于定位 IPC 通信问题非常重要。同时，用户体验的改善往往需要从错误处理开始，友好的错误提示和操作引导能够显著提升应用的可用性。
