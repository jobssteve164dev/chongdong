## 2. 核心实现 (Core Implementation)

### a. 方法论/设计思路
- 复用既有“代理链中间件架构”（`ProxyChainMiddlewareManager` + `TrafficRouter` + `ProtocolAdapter`）。
- 新增“CF Edge 出站”作为可插拔策略：通过应用层封装（HTTPS + HMAC + 时间窗）在边缘解封装并转发。
- 页面新增“边缘网络”Tab 提供启用开关、端点、PSK/ID、策略（全局/非大陆/白名单/黑名单）与白/黑名单配置。
- 安全优先：在 Worker 侧强制签名校验、时间窗、私网阻断、速率限制、MIME白名单、响应大小上限与敏感头屏蔽，降低被识别与滥用风险。

### b. 主要变更文件 (Key Changed Files)
- CREATED: `edge/_worker.js`（HMAC/时间窗校验、私网阻断、速率限制、MIME白名单、响应上限、最小化响应头）
- CREATED: `src/main/services/cfEdgeClient.ts`（客户端封装与签名发送）
- CREATED: `src/main/services/cnCidrManager.ts`（下载并管理离线CN CIDR库）
- CREATED: `src/main/services/geoResolver.ts`（基于DoH/DoT解析+离线CN CIDR判定的“非大陆”解析器）
- CREATED: `docs/edge-worker-config.md`（Worker 可定义配置说明）
- MODIFIED: `src/main/trafficRouter.ts`（命中策略时走Edge并回写HTTP响应；失败回退本地链路）
- MODIFIED: `src/main/services/dnsService.ts`（新增 `resolveDomainOnce` 便于一致性解析）
- MODIFIED: `src/shared/types/index.ts`、`src/shared/defaultSettings.ts`（新增 `cfEdgePolicy`、PSK/Endpoint等配置字段与默认值）

## 3. 验证与测试 (Verification & Testing)

### a. 验证方法
1. 构建验证：`npm run build`（主/渲染/产物electron）
2. 功能验证：
   - 设置 → 边缘网络：配置`cfEdgeEndpoint`、`cfEdgePSK/PSKId`、策略与白/黑名单；
   - 访问典型域名：命中“白名单/非大陆/全局”策略时首包走Edge，Worker返回200；非命中或失败回退本地链路；
   - 错误场景：签名错误/超时401、私网直连403、速率超限429、MIME不白名单415、超大响应被截断。
3. 非大陆策略：通过DoH/DoT解析域名IP并与离线CN CIDR匹配，CN返回直连/非CN走Edge（依配置）。
4. 文档：`docs/edge-worker-config.md` 对部署配置、KV绑定、环境变量进行说明。

## 4. 影响与风险评估 (Impact & Risk Assessment)

- 正面影响：
  - 隐匿ISP可见目标与对端可见IP；
  - 灵活策略（全局/非大陆/白/黑名单）；
  - 强化安全（签名/时间窗/速率/MIME/体积/私网阻断/头部最小化）。
- 潜在风险/后续工作：
  - Geo 离线库来源依赖稳定性，建议周期性更新并增加备用源；
  - 对HTTPS/TLS隧道的通用处理仍可进一步扩展（当前重点覆盖HTTP明文首包GET）；
  - Worker端加入更多审计日志（需注意不暴露敏感信息）。
