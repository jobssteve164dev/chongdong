# 修复启动代理按钮错误报告

## 问题描述

用户反馈点击首页的"启动代理"按钮时出现"指定的节点不存在"错误，且没有任何调试信息产生，说明错误在函数执行之前就抛出了。

## 错误分析

### 初始错误
- **错误信息**: "指定的节点不存在"
- **现象**: 点击按钮后直接返回错误，没有任何调试信息
- **根本原因**: `nodeLatencies` Map 对象在序列化/反序列化过程中出现问题，导致调用 `.get()` 方法时抛出 `TypeError: m.get is not a function`

### 调试过程

1. **添加调试信息**: 在 `handleStartNodeProxy` 函数开始处添加 console.log 来跟踪执行流程
2. **发现作用域问题**: 在添加 try-catch 错误边界时破坏了变量作用域，导致 `connectionStatus is not defined` 错误
3. **修复作用域问题**: 移除错误的 try-catch 结构，恢复正常的组件结构

## 技术修复

### 1. 修复 Map 对象序列化问题

**文件**: `src/renderer/utils/stores.ts`

**问题**: `nodeLatencies` 在某些情况下不是 Map 对象，导致 `.get()` 方法调用失败

**解决方案**:
```typescript
// 为所有 nodeLatencies.get() 调用添加 Map 类型保护
const latency = nodeLatencies instanceof Map ? nodeLatencies.get(nodeId) : undefined;
```

**修改位置**:
- `getBestNode()` 函数中添加 Map 类型检查
- `setNodeLatency()` 函数中添加 Map 类型保护
- 反序列化函数中添加错误处理和类型验证

### 2. 增强 getBestNode 函数

**改进逻辑**:
```typescript
getBestNode: () => {
  const state = get();
  
  // 确保 nodeLatencies 是 Map 对象
  if (!(state.nodeLatencies instanceof Map)) {
    console.warn('nodeLatencies 不是 Map 对象，重新初始化');
    // 如果没有延迟信息，返回第一个节点
    if (state.nodes.length > 0) {
      return state.nodes[0];
    }
    return null;
  }
  
  // 首先尝试找到有延迟信息且延迟大于0的节点
  const availableNodes = state.nodes.filter(node => {
    const latency = state.nodeLatencies.get(node.id);
    return latency && latency > 0;
  });
  
  if (availableNodes.length > 0) {
    // 按延迟排序，选择延迟最小的节点
    return availableNodes.sort((a, b) => {
      const latencyA = state.nodeLatencies.get(a.id) || Infinity;
      const latencyB = state.nodeLatencies.get(b.id) || Infinity;
      return latencyA - latencyB;
    })[0];
  }
  
  // 如果没有延迟信息，返回第一个节点
  if (state.nodes.length > 0) {
    return state.nodes[0];
  }
  
  return null;
}
```

## 经验总结

1. **数据持久化问题**: 复杂数据类型（如 Map）在序列化时需要特殊处理

3. **调试技巧**: 当错误没有调试信息时，应该从最基础的层面开始排查
4. **组件结构**: 保持 React 组件的标准结构，避免破坏变量作用域
