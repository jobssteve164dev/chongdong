## 2. 核心实现 (Core Implementation)

### a. 方法论/设计思路
采用了统一的代理状态清理机制，创建了一个核心的 `cleanupProxyState()` 函数，确保在所有需要清理代理状态的场景下都能彻底清理：
1. 停止中间件管理器
2. 停止所有代理进程
3. 清理系统代理设置
4. 等待进程完全退出

### b. 主要变更文件 (Key Changed Files)
*   `MODIFIED`: `src/main/index.ts` - 添加统一清理函数和优化退出逻辑
*   `MODIFIED`: `src/renderer/pages/ProxyManagement.tsx` - 在启动新代理前添加清理逻辑

### c. 关键代码片段 (Optional but Recommended)

**示例: 统一的代理状态清理函数**
```typescript
// src/main/index.ts
async function cleanupProxyState(): Promise<void> {
  try {
    console.log('开始清理代理状态...');
    
    // 1. 停止中间件管理器
    await proxyManager.stopMiddleware();
    
    // 2. 停止所有代理进程
    await proxyManager.stopAll();
    
    // 3. 清理系统代理设置
    await systemProxyManager.clearSystemProxy();
    
    // 4. 等待一段时间确保进程完全退出
    await new Promise(resolve => setTimeout(resolve, 1000));
    
    console.log('代理状态清理完成');
  } catch (error) {
    console.error('清理代理状态失败:', error);
    throw error;
  }
}
```

## 4. 影响与风险评估 (Impact & Risk Assessment)

*   **正面影响**: 
  - 解决了程序退出时代理进程残留的问题
  - 解决了切换代理时状态冲突的问题
  - 提高了系统的稳定性和用户体验
  - 统一了代理状态管理，降低了维护复杂度

*   **潜在风险/后续工作**: 
  - 清理过程增加了1秒的等待时间，可能影响用户体验
  - 需要在实际使用中验证清理的彻底性
  - 建议添加清理过程的进度提示，让用户了解当前状态

## 5. 自我评估与学习 (Self-Assessment & Learning)

*   **遇到的挑战**: 
  - 需要确保在所有代理启动场景下都添加清理逻辑
  - 需要平衡清理的彻底性和用户体验
  - 需要处理清理过程中的异常情况

*   **学到的教训**: 
  - 统一的清理机制比分散的清理逻辑更容易维护和调试
  - 在异步操作中添加适当的等待时间可以避免竞态条件
  - 错误处理应该允许清理过程中的非致命错误，但不应该影响主要功能
