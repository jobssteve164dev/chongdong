## 2. 核心实现 (Core Implementation)

### a. 方法论/设计思路
采用了分层防护架构，从网络策略层到应用层全面加固HTTP/2.0隐私保护。核心思路包括：
1. **网络策略层**：禁用QUIC/HTTP3，阻断UDP直连，防止Alt-Svc升级绕过代理
2. **协议管理层**：实现敏感域强制HTTP/1.1降级，启用连接隔离，防止连接合并泄露
3. **指纹标准化层**：统一TLS ClientHello指纹和HTTP头部，消除浏览器指纹差异
4. **DNS/IPv6统一层**：强制所有DNS查询通过代理DoH/DoT，禁用IPv6直连
5. **验证监控层**：实现端到端测试脚本，验证HTTP/1.1与HTTP/2.0出口一致性

```typescript
// src/main/services/httpHeaderProtectionService.ts
public sanitizeHeaders(headers: { [key: string]: string }, template: 'chrome' | 'firefox' | 'safari' | 'edge' = 'chrome'): { [key: string]: string } {
    if (!this.enabled) {
        return headers;
    }

    const baseHeaders = { ...this.headerTemplates[template] };
    const sanitizedHeaders: { [key: string]: string } = {};

    // Apply neutral Accept-Language if configured to hide language
    if (this.mode === 'strict') {
        baseHeaders['Accept-Language'] = 'en-US,en;q=0.9';
    }

    // Remove sensitive headers
    for (const sensitiveHeader of this.sensitiveHeaders) {
        delete sanitizedHeaders[sensitiveHeader];
        delete sanitizedHeaders[sensitiveHeader.toLowerCase()];
    }

    return sanitizedHeaders;
}
```

**示例: 端到端出口一致性测试**
```typescript
// src/main/scripts/testHttpEgressConsistency.ts
async function run(): Promise<void> {
  console.log('=== HTTP/1.1 vs HTTP/2 出口一致性测试 ===');
  const services = [
    { host: 'ipinfo.io', path: '/json' },
    { host: 'ipapi.co', path: '/json' }
  ];

  for (const svc of services) {
    const h1 = await fetchHttp1Json(svc.host, svc.path);
    const h2 = await fetchHttp2Json(svc.host, svc.path);
    const consistent = !!(h1.success && h2.success && h1.ip && h2.ip && h1.ip === h2.ip);
    console.log(`${consistent ? '✅' : '❌'} ${svc.host}${svc.path}: ${h1.ip || 'N/A'} vs ${h2.ip || 'N/A'}`);
  }
}
```

## 5. 自我评估与学习 (Self-Assessment & Learning)

*   **遇到的挑战**: 
    - 在实现HTTP头部标准化时，需要平衡隐私保护与网站兼容性
    - 端到端测试脚本需要处理复杂的网络连接和TLS握手过程
    - 确保所有防护措施在严格模式下不会影响正常网络访问

*   **学到的教训**: 
    - 隐私保护需要从多个层面协同工作，单一措施往往不够充分
    - 端到端验证是确保防护措施有效性的关键，不能仅依赖理论分析
    - 在实现复杂功能时，应该先建立测试框架，再逐步完善实现细节
    - 代码的可测试性和模块化设计对于维护和调试至关重要
